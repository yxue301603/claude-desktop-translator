# 本机验收记录

## 0.4.0 插件版（2026-10-19）

环境：Windows、Node.js 24.19.0、Claude Desktop 2.42304.2 普通 Chat。以 `.mcpb` 安装到 Claude 的 Extensions，完成原生安装确认、MCP 初始化、工具和提示模板发现、自动启动伴随窗口、停用及重新启用。测试过程中没有读取登录令牌，也没有调用第三方 Gateway 或翻译 API。

### 不安装本地模型的实际验证

测试前确认本任务曾启动的 Ollama 没有加载模型，停止该空闲进程；保留已有权重文件。随后使用桌面当前登录的 Claude 官方账号完成以下两项真实端到端测试。中文原文与英文流程指令一起发出，Claude 生成英文理解、英文回答和完整中文，伴随窗口提取完整中文。两项测试的实际提交预览均包含完整原文；完整中文提取结果与窗口显示逐字一致（仅统一 Windows 换行表示）。

| 样例 | 人工逐项核对内容 | 结果 |
|---|---|---|
| 四句自我介绍 | 身份、协助写作、解释代码、可能犯错、末尾询问目标；四句均有对应译文 | 通过 |
| 条件、数字及代码 | 只有测试通过才能继续；耗时不超过 250 毫秒；不得执行、删除或上传；两行 JavaScript 原样保留 | 通过 |

原文与真实生成结果保存在 [账号模式验收样例](account-acceptance-results.json)，输入样例也见 `test/fixtures/account-acceptance.json`。这些都是为本项目编写的测试文本，没有包含用户既有对话或账号资料。

四句介绍实际显示为：

> 我是 Claude，由 Anthropic 开发的 AI 助手。我可以协助你写作，也可以为你解释代码。我可能会犯错，所以在依赖重要内容之前，请务必再次核实。你希望完成什么任务呢？

第二项的限制回译为：

> 限制条件：只有测试通过且耗时不超过 250 毫秒时才能继续，并且不得执行代码、不得删除文件、不得上传数据。

两项精查确认了这些句子的完整句意，没有把模型生成成功或格式检查通过当成所有文本的准确率。复杂 Markdown、表格和代码语言标签可能不能由辅助功能完整还原；示例中的代码字符、换行和数值已单独核对。

### 本轮修复与回归范围

- Claude 内置 Node 运行时直接托管回环服务，不误把 `Claude.exe` 当作独立 Node 进程；监听回调在绑定端口前注册。
- Windows PowerShell 用 Unicode 编码命令启动，真实执行测试覆盖空格、中文和单引号路径；避免此环境下 detached 子进程退出却未执行的问题。
- 新版 Claude 输入框的完整文本范围会省略空段落。修复后按实际段落节点严格重建，保留连续空段落、行内代码和标点；内容校验仍能拒绝数字或正文变化。
- 延续 0.3.1 的全文读取修复：不用首句摘要替代正文，等待生成结束及正文稳定，正文增长后允许重新处理。
- 实测停用/启用扩展，未发送的测试草稿由 Windows DPAPI 加密保存并精确恢复；清空后删除恢复文件。
- 28 项 Node 测试覆盖真实 MCP stdio、五个工具、动态提示模板、两种模式、完整/不完整回答、回环鉴权及已有离线翻译逻辑。Windows 回归另覆盖真实辅助功能正文与段落重建。
- 官方 MCPB 校验与打包通过；从独立目录解压最终安装包后启动其真实 MCP 进程，检查工具、提示模板、账号模式不要求模型，以及私有文件和开发工具未打包。

生产依赖审计为 0 个已知漏洞。官方 MCPB 开发工具的签名依赖 `node-forge` 在审计时仍有 2 项 high 提示且没有可用修复版本；该开发依赖不进入安装包，本项目未执行签名操作。SHA-256 见随安装包发布的 `SHA256SUMS.txt`。

### 明早验收

1. 打开 Claude 普通 Chat；本机已安装并启用 0.4.0。确认窗口标题为 `Claude 中英翻译 · 账号双语 · v0.4.0`。窗口已关闭时，在 Extensions 中停用再启用本扩展即可重新打开。
2. 在伴随窗口输入：`请用英语分四句话介绍你自己，最后一句询问我想完成什么任务。不要使用工具。`，按 Enter。
3. 等待 Claude 完成，核对伴随窗口的中文包含完整四句及末尾提问。预览明确显示实际提交含中文原文。
4. 该模式不用启动 Ollama。若仍出现旧的 Ollama 启动报错，请确认使用的是 0.4.0 扩展，并关闭“使用离线预翻译”设置及旧版独立窗口。

原有“先本机译成英文，只发送英文”的要求仍由可选 `offline` 模式实现；默认免模型方案不能同时满足“Claude 完全收不到中文原文”。普通 Chat 的官方插件能力没有全局输入/输出拦截 Hook，扩展因此保留伴随窗口。详见 [使用说明](plugin-guide.md)。

## 0.2.0–0.3.1 历史验收

验收日期：2026-10-16。环境：Windows、Node.js 24.19.0、Claude Desktop 2.37337.1 的普通 Chat。

使用桌面应用中已登录的官方账号完成了以下流程，没有调用 Gateway 或第三方翻译 API：

- 在伴随窗口输入中文，离线模型生成英文；草稿校验后，实际点击 Claude 官方发送按钮。
- 读取 Claude 实际生成的英文回答，在伴随窗口显示本地中文译文。
- 行内命令 `npm test` 在输入、官方回复与中文译文中保持完整。
- 中文指令附带两行 JavaScript 围栏代码，英文提交保留代码内容和换行；Claude 返回解释及原代码，回译中的代码也保持完整。
- 发送前后比较系统剪贴板的文本与格式，确认临时粘贴后恢复原内容。检查过程不打印剪贴板内容。
- 从真实回复中提取正文，排除操作按钮、代码语言标题和推广卡片。

以上为 0.2.0 的桌面集成验收。0.3.0 更换为 Hy-MT2 专用翻译模型并保留完整上下文，15 项 Node 回归测试与 Windows PowerShell 编译通过。真实模型的 `doctor` 只向回环地址发出推理请求。另完成 20 条双向译文和一篇跨两次推理的长文核对，原文、实际译文与检查范围见[翻译质量报告](translation-quality.md)。

0.3.1 补充了桌面多句回答验收。0.3.0 的模型测试未覆盖以下读取缺陷：Claude 的隐藏辅助功能摘要仅含首句；部分原始视图中的正文容器，使用 `FindAll(Descendants)` 查询却返回空集合。旧代码在此时退回首句摘要，并依据摘要判断回答未变化，最终只显示第一句的译文。

修复后从消息节点枚举文本，再逐个检查原始祖先是否属于正文。摘要只用于识别回答者，正文不可用时等待重试。正文稳定至少 1.5 秒且没有检测到生成按钮时开始翻译，去重依据完整正文；正文后续变化可再次翻译。窗口标题从 `package.json` 读取版本号。

在同一个真实 Claude 会话中，修复前提取结果为首句摘要；修复后读取到全部 240 个字符（四句话），无需重新发送消息。实际离线译文如下，已核对身份、能力列表、版本名称和末尾问句均保留：

> 我是 Claude，由 Anthropic 开发的 AI 助手。我可以协助写作、回答问题、解释代码、进行数学计算、头脑风暴、分析文档等等。这个版本是 Claude Sonnet 5.5。你想做什么工作呢？

该译文中的版本名称来自测试时 Claude 的原始回答。新增 Windows 回归测试覆盖多节点完整正文、原始祖先定位、正文外文字排除、禁用摘要回退、生成中等待、完整正文变化后重新处理、失败重试及不同会话的相同文本。

小型离线模型的翻译质量有限，可能误译术语；辅助功能也不能完整还原复杂 Markdown。验收确认的是实际发送、读取、回译及示例代码保留，不代表所有文本都能准确翻译。请按 README 核对英文预览与 Claude 原文。
